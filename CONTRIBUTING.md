## Getting started

1. **Prereqs:** Node ≥20, Bun ≥1.0 (`bun -v`, `node -v`).
2. **Clone & install:** `git clone https://github.com/poferraz/vibe-fence.git && cd vibe-fence && bun install`
3. **Authority:** Implement runtime changes in `src/`; `dist/` is generated and disposable (`bun run build`). Tests, tools, and documentation live in their respective directories.
4. **Governance:** See `CODE_OF_CONDUCT.md` and `SECURITY.md`. License is MIT.

## Verify before opening a PR

```sh
bunx --no-install tsc --noEmit
bun run build
bun run validate
bun test
bun run eval
bun pm pack --dry-run
```

Run these in order and report skipped tests or unknown results. CI runs the full suite on Linux and macOS and a portable hook smoke test on Windows while Unix-specific fixtures are being adapted. See the [maintainer checklist](docs/MAINTAINER.md) and [evaluation ladder](docs/EVALUATION-LADDER.md) for release checks and the limits of each measurement.

## Project conventions

- Do not edit `dist/` by hand — it is regenerated by `tools/generate.ts` (includes `dist/cli.js` publishable bin).
- Do not skip `bun run validate` — it checks `AGENTS.md` token budget, context budgets, and freshness.
- Do not use "Turbo" in user-facing copy — name bands by guarantee (see FINAL-v4 §2 S-10; S-10 unchanged from v2).
- Adding a rule: create `src/rules/<id>.ts` + register in `src/rules/index.ts` + entry in `src/config/severity-policy.json`.
- Adding an adapter: `src/adapters/<name>.ts` + `src/adapters/<name>.yml` (profile), see `src/adapters/types.ts`.
- Track work against `FINAL-v4.md` §4 M1–M4 checklist where applicable.

## Pull requests

- Keep PRs focused; reference the relevant M1–M4 item from `FINAL-v4.md` §4.
- Fill out the PR template (`.github/pull_request_template.md`).
- CI must be green; branch protection requires it on `main`.

## Security

See `SECURITY.md` — use private vulnerability reporting for guardrail bypasses, secret leaks, or integrity issues, not public issues.
