## Top 10 issues (ranked; each: severity P0/P1/P2, file:line, one-line fix, effort S/M/L)

1. **P1 — Git protection examines the wrong content.**  
   Hooks invoke a working-tree scan. I staged a prohibited reference, cleaned the working file without restaging, and successfully committed the prohibited blob. I also checkpointed it, committed a fix, then successfully pushed the contaminated history to a local bare remote. Checkpoint deliberately bypasses hooks. [git-hooks.ts:28](../../../src/framework/git-hooks.ts#L28), [check.ts:100](../../../src/check.ts#L100), [git.ts:129](../../../src/framework/git.ts#L129), [reproduction](/tmp/vibe-fence-audit/repro.log).  
   **Fix:** Scan index blobs before commits and every newly outgoing commit before pushes; add both reproductions. **Effort: M.**

2. **P1 — The advertised one-command installation does not establish durable enforcement.**  
   The npm registry returned HTTP 404 for `vibe-fence`. Separately, hooks and the OpenCode plugin rely on a later PATH lookup or manually supplied `FENCE_BIN`; when absent, they allow operations. A fresh scratch installation allowed my prohibited commit with “binary not found … skipping check.” [README:15](../../../README.md#L15), [git-hooks.ts:33](../../../src/framework/git-hooks.ts#L33), [opencode.ts:82](../../../src/adapters/opencode.ts#L82), [npm response](/tmp/vibe-fence-audit/npm.json).  
   **Fix:** Establish a durable executable during installation, report enforcement health accurately, and validate the actual published-package journey. **Effort: M.**

3. **P1 — Generated OpenCode configuration violates its published schema.**  
   Installation inserts a top-level `fence` property. The current official schema has no such property and sets top-level `additionalProperties: false`. Existing tests import the plugin directly, bypassing host configuration loading. This is a confirmed schema mismatch; I did not launch OpenCode to observe its runtime error. [opencode.ts:43](../../../src/adapters/opencode.ts#L43), [plugin test:29](../../../src/adapters/opencode-plugin.test.ts#L29), [official schema](https://opencode.ai/config.json).  
   **Fix:** Store private metadata under `.fence/`, use supported host configuration, and test startup with a pinned OpenCode version. **Effort: M.**

4. **P1 — Meta and verification are not connected to the user workflow.**  
   Production-reference searches found no callers of `companionCall`, `architectCall`, or `runTrustLadder` outside their defining modules; the probe alone calls `callResponses`. The CLI dispatches deterministic commands. SAM uses `/v1/sam/segment`, whereas the documented interface uses `/v1/responses` with `sam-3.1`; `fence-look` can return a stub “pass” without verification. [cli.ts:7](../../../src/cli.ts#L7), [sam.ts:116](../../../src/framework/sam.ts#L116), [fence-look.ts:171](../../../src/framework/fence-look.ts#L171), [SAM documentation](https://dev.meta.ai/docs/media-segmentation).  
   **Fix:** Ship one real blocked-action → Spark repair proposal → user approval → mechanical verification flow, and remove unsupported feature claims. **Effort: L.**

5. **P1 — Ordinary invocation variations bypass the live gate.**  
   My packed-CLI probes blocked `./demo.sh` but allowed `bash ./demo.sh` containing the same prohibited pipeline. They also allowed destructive SQL through `psql -c`, a secret-bearing `apply_patch`, and a write whose prohibited content followed 64 KiB of padding. No destructive payload was executed. [gate.ts:83](../../../src/framework/gate.ts#L83), [gate.ts:130](../../../src/framework/gate.ts#L130), [context.ts:61](../../../src/rules/context.ts#L61), [reproduction](/tmp/vibe-fence-audit/repro.log).  
   **Fix:** Normalize supported host tool schemas and interpreter commands, enforce SQL execution checks, and reject or explicitly downgrade uninspected inputs. **Effort: L.**

6. **P1 — Integrity protection is not an enforced security boundary.**  
   Changing attested `AGENTS.md` failed the direct integrity verifier but passed `runCheck`. Any nonempty `FENCE_SYNC_TOKEN` bypassed verification, and re-attestation succeeded without a token. The installed postinstall wrapper suppresses failure with `|| true` and references a project-relative development tool. [integrity.ts:87](../../../src/framework/integrity.ts#L87), [integrity.ts:137](../../../src/framework/integrity.ts#L137), [install.ts:263](../../../src/install.ts#L263), [reproduction](/tmp/vibe-fence-audit/repro-eval.log).  
   **Fix:** Wire integrity verification into installed enforcement and place any claimed authorization boundary outside agent-controlled files/environment. **Effort: L.**

7. **P1 — “Held-out” and baseline guarantees are overstated.**  
   Cases substantially repeat unit-test patterns; the `.env` fixture `K=v` appears in both suites. There is no documented blind split or tuning history. More seriously, deleting **all 24 positive cases** still yields no baseline regressions; an empty report also passes the comparator. It checks ratios, not preserved coverage. The review-before-commit policy is only a printed warning. [corpus:20](../../../tests/evals/corpus.json#L20), [sec-03.test:49](../../../src/rules/sec-03.test.ts#L49), [eval.ts:148](../../../tools/eval.ts#L148), [reproduction](/tmp/vibe-fence-audit/repro-eval.log).  
   **Fix:** Version and hash case IDs/labels, require rule and case coverage, prohibit unexplained skips, and freeze an independently reviewed test split. **Effort: M.**

8. **P1 — Partner red-team metrics would currently be misleading.**  
   FS-01 receives neither the generated path as `filePath` nor a project root; PRV-09 receives `probe.ts` outside fixture scope; SUP-01 JSON receives `probe.sh`. Mocked malicious responses missed all three. “Caught by either tree or live lens” also hides which deployed surface actually protects the user. 9. **P1 — The required demo artifact is absent, and the script exceeds delivered behavior.**  
   The checklist lacks the three-minute YouTube link. The README promises Spark plan cards, generated imagery, and deployment behavior without corresponding verified end-to-end evidence. Passing CI does not establish those claims. [SUBMIT:16](../SUBMIT.md#L16), [README:73](../../../README.md#L73).

## Verdict (3 sentences max: place or not, the single biggest reason, the single highest-ROI fix)

I would not place this submission today. The biggest reason is that the promised safe, Meta-powered companion is not demonstrated end to end: enforcement bypasses are reproducible, while Meta’s verified contribution remains a connectivity probe. The highest-ROI fix is one fully tested supported-host workflow that blocks a real mistake, uses Spark to propose a repair, mechanically verifies the result, and appears in the required three-minute video.
