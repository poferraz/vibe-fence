## 2. Where they disagree

> In a stream this thin, some disagreements are really "contributor A investigated X, contributor B did not." Those are listed in §3 (unique contributions), not here. This section is reserved for direct conflicts on the same design question.

### D-01 — What is "max" on the dial? Explain loudly vs. hint-first vs. structured forcing vs. expanded card

- **Reading A (gemini, leaning muse-spark):** `max` is *pedagogical scaffolding*: explain the engineering concept + why it matters + vulnerability prevented + solution pattern. muse-spark's T-01 spec includes a retrieval prompt ("why do you think we rejected empty strings?") on top of the explanation. The card is *expanded* and verbose.
- **Reading B (deepseek):** `max` is *hint-first*: start with the symptom + one question (offer, non-blocking, with timeout), escalate to explanation only if the user misses or ignores. Never explain a fix before the user has had one chance to react. Retrieval budget: 1 question/session, first occurrence only. Store answers in `.fence/state/learning.json` so the same concept is never re-quizzed.
- **Reading C (minimax, built on Buçinca et al. + IUI '25):** Verbosity is the wrong axis entirely. `max` is *structure + cognitive forcing*: a fixed block schema at every level (`What I'm doing / Why / Your call (2 options + trade-offs) / What I won't do / How we'll know`), with a forced-choice moment at decisions that carry real trade-offs. The most effective forcing designs get the *worst* subjective ratings and help high-Need-for-Cognition users most — the protective design is the one beginners will most want to turn off.
- **Resolution:** None of the three ships in the others' form today, so there is nothing to copy — this is a judgment call a design lead must make now, then validate. Proposed synthesis for Phase 2: **minimax's schema as the container** (every level is the same structured card; the dial fills fewer blocks as it quiets), **deepseek's hint-first rule as the inside-the-block policy at `max`** (first occurrence of a pattern in a domain → question before answer; timeout → explanation), and **muse-spark/gemini's vulnerability narrative as the content of the `Why` block**, not as free prose. The disagreement is narrower than it looks: everyone converges on "not just more words" once the evidence is in. The remaining conflict is whether `max` should sometimes *withhold* the answer to force retrieval, and that depends on whether the user came to learn or to ship — which leads to D-02.
- **Why it matters for Phase 1:** Determines the `.fence/learn/*.md` authoring rule, the injected prompt text per dial level, and the Phase 2 demo-day success metrics (Bastani et al.'s 48%→−17%→+127% numbers are math-task numbers; vibe-fence's domain is code, and no study measures the transfer — all contributors flag `contested` for the coding transfer).
- **Thinned-stream note:** argon and gpt-6 were absent. Both were strong on primary-source education studies in other streams. Without their read on Bastani vs Buçinca vs ICAP, this three-way split cannot be treated as comprehensive. Phase 2 should run one transfer check: can a user who saw the `max` card fix a *similar* issue unassisted next time?

### D-02 — Per-domain fade vs. per-user fade vs. invisible competence tracker: who moves the dial and when?

- **Reading A (muse-spark):** Default newcomers to `max`; auto-suggest lowering after N consecutive successful verifications of the same rule (N=5). User-controlled opt-in to each step-down (`You're nailing input validation — want shorter explanations?`). Security always teaches one line even in `silent`.
- **Reading B (deepseek):** Vector dial over ~7 domains; step a *domain* down after (a) correct retrieval answer in that domain, (b) three consecutive accepted changes in that domain, or (c) explicit "I know this." Step the domain back *up* on reversal/incident. Never reset silently. Teaching channel (concepts) is mute-able; consequence channel (what changed/touched/undo) is always on — `silent` still gets a one-line-per-change digest.
- **Reading C (minimax):** Fade schedule is the active ingredient; dial is per-task-class (same claim as deepseek's vector). Add a decaying *teaching budget* (Steyvers & Mayer 2025 POMDP) as the runtime governor: every teaching moment spends budget; repeated dismissals lower it automatically; `silent` is a *policy* rather than a setting. Also: auto-degrade under context pressure even if the user did not ask.
- **Reading D (gemini):** Single `teaching_dial` key in `.fence/config.json`; default `medium` (contradicted by everyone else, who default to `max` for new users). No per-domain state; no budget; no auto-degrade rule.
- **Resolution:** gemini's single-key default is superseded by the three more recent, better-sourced specs. Phase 1 should ship the **state file as the architecture even if the UI stays simple**: `.fence/state/dial.json` keyed by domain, with a global shortcut that steps all domains together in v1 UI. The budget/auto-degrade rule (minimax) is defensible but unmeasured; treat it as an opt-in Phase 2 experiment flag (`--budgeted-teaching`), not a v1 default. The two-channel split (deepseek T-06: teaching mute-able, consequence always on) is the cleanest framing and should be normative spec language — it resolves the recurring "what does `silent` mean for `block`-tier?" argument that otherwise haunts every implementation discussion.
- **Why it matters for Phase 1:** Determines `.fence/` schema stability. Retrofitting per-domain state later is expensive; shipping it hidden now is cheap. The `config.json` vs `config.yaml` filename bikeshed should be settled by whatever M1's template already chose; the important decision is *vector vs scalar*, not the file extension.
- **Thinned-stream note:** Only 2/4 contributors made the vector argument forcefully (deepseek, minimax); muse-spark noted it in a config footnote; gemini missed it. In a fuller stream the minority reading might have surfaced a counterargument (e.g. cognitive-load cost of per-domain state). No counterargument appeared — but absence of a challenge in N=4 is not evidence there isn't one.

### D-03 — Turbo's mechanism: deterministic containment vs. classifier-in-the-loop vs. prompt-based permission wrapper

- **Reading A (muse-spark):** Three tiers (auto/notify/gate) with tiered *dwell* (3s for nudge, 5s for warn) + abort, payload hashing/pin at approval, and a plan artifact (`.fence/plans/<task>.md`) per approval. Safety is an orchestration of tier + plan + checkpoint + pin.
- **Reading B (deepseek):** Containment + reversibility is the thesis; prompts are explicitly called theatre on scope/credential exfiltration (`npm run *` missed 52.5%, scope reads 35%). Introduce a *three-condition gate test*: a gate is only permitted if it can show (1) resolved target (post-`realpath`, post-symlink), (2) diff/blast radius, and (3) a decision the user is competent to make — otherwise contain/fix/defer. Gate budget capped at 3/session; auto-demote on >90% approval rate.
- **Reading C (minimax):** Vendors converged on a *classifier in the loop* at Claude Code/Codex/Cursor; turbo = "replace the human with a classifier for the action classes where a classifier is reliable" + four-band autonomy (`off/low/medium/high`, Factory Droid shape, blocklist holds at every band). Also: friction ladder per action, not per session; never blanket confirm/blanket skip.
- **Reading D (gemini):** "Teachable Turbo" — auto approvals for files/npm/tests, hard pause on destructive DB/money/deploy, git-checkpoint insurance; presented as an `AGENTS.md` contract rather than a technical mechanism.
- **Resolution:** The *shape* is now settled across all four (tiers + gate list + checkpoints + plan), but the *mechanism* is not. muse-spark's payload-pin and dwell times, deepseek's three-condition test and budget self-awareness, and minimax's classifier architecture are complementary, not conflicting — they address orchestrated review (muse-spark), prompt-legitimacy gating (deepseek), and classification cost (minimax) respectively. Minimal v1 (to prove "less nagging, more safety" is falsifiable) is: **(1)** deepseek's perimeter + undo (project-root `realpath` + credential hard-deny + egress allowlist + one-command rollback), **(2)** muse-spark's plan artifact + payload pin, **(3)** minimax's four-band naming by guarantee (not "Turbo"). The classifier can be flagged for Phase 2; deepseek explicitly counsels against building a classifier-based gate for v1 (unevaluated non-zero miss rate, evaluation burden). gemini's contract-only approach (prompt-only guardrail) is superseded: Cursor's own docs concede its allowlist is "best-effort, not a security boundary."
- **Why it matters for Phase 1:** Decides whether M2 builds a model-classifier or a deterministic fence, which has radically different latency/cost/evaluation properties. Also determines the Phase 2 demo's falsifiable metrics: gate count per session, approval rate (rolling 20), findings resolved without asking — all proposed by deepseek with vendor-grade anchors.
- **Thinned-stream note:** gpt-6 (absent) had strong coverage of LLM serving/inference cost models in Stream 02; its view on classifier latency for an on-device fence is exactly the gap no present contributor can fill.

### D-04 — Should onboarding front-load teaching ("explain the plan before the first build") or delay it ("artifact first, teach after")?

- **Reading A (muse-spark, implicitly gemini):** After `npx vibe-fence init`, run an interactive tour (`fence tour`) that triggers a mock finding + fix to teach the card UX; paved 3-step path ("1. keep building… 2. you'll see a card… 3. approve and the agent handles it") — onboarding *is* a lesson before the first real build.
- **Reading B (deepseek, minimax):** Onboarding is the product, and it is one prompt → working artifact from the first message (Bolt/Lovable/v0 pattern; Lovable "start building immediately" + Replit "no code required"). Teaching about the artifact comes *after* the artifact (minimax O-02: "the first run should produce the artifact first and teach about the artifact afterwards — the opposite of explaining the plan before the first build," consistent with pre/post explanation timing: pre-explain only when reliability is low; a first "make me a landing page" is reliable). Fontys report's lesson: the beginner's blocker is not the concept, it is the filesystem — so the harness must absorb the prompt and the filesystem entirely. Both deepseek and minimax want the install to print ~2 lines and then go silent until there is a fix to deliver.
- **Resolution:** Both readings describe the same funnel; the disagreement is on the first 60 seconds of attention. Proposed synthesis: **artifact first, tour on demand.** `npx vibe-fence init` prints what was installed + `fence tour` hint. The first real build proceeds with zero teaching overhead. The first fence output is a *completed fix*, not a warning (Q-01, minimax O-05). `fence tour` (mock card → approve → fixed → green check, per muse-spark) exists and is mentioned by the plan file, but is opt-in. This resolves the contradiction: muse-spark's "interactive tour" is preserved; deepseek/minimax's "invisible until it has a fix" default is preserved; gemini's single-command init is shared by all 4. Teaching-before-building (Replit "Plan toggle → ordered task list" at scale) becomes appropriate *after* the first artifact, when the user has a mental model to anchor the plan to.
- **Why it matters for Phase 1:** Determines whether M4's installer generates an interactive first-run flow (higher onboarding friction, higher early learning) or a minimal silent harness (lower friction, higher activation). The "editable draft" loop (minimax O-05), the one-prompt artifact path (deepseek O-01), and the plan-as-interface (minimax O-03) all point artifact-first.
- **Thinned-stream note:** No contributor published card-reading-rate data (deepseek gap #3, muse-spark gaps). Claims about "users read the plan" are design inferences, not measurements.

## 4. Gaps in the collective research

> What NOBODY found. Larger and more consequential than in other streams because the two absent contributors (argon, gpt-6) often supplied the primary-source anchors for contested claims elsewhere. Gaps are grouped.

1. **No controlled evaluation of a teaching-verbosity dial in a coding tool exists.** Every dial finding is transferred from math/physics/legal-reasoning instructional psychology (Bastani et al. is high-school math; scaffolding meta-analyses are online higher-ed) plus product observation (Claude Code output styles, Replit Plan mode). The dial's specific cut-points are design judgment, not evidence. — All 4 contributors flag this; minimax §6 lists it first. **Close with:** a transfer check in Phase 2 evals (can a user fix a similar issue unassisted after seeing one card?). Until then treat A-01/A-02 as well-motivated, not settled.

2. **No vendor publishes card-reading-rate or plan-card comprehension data.** Replit's Plan mode, Lovable's spec flow, v0's Code view are documented mechanically; none publish whether users actually read them. "Users read the plan" is a design inference throughout. **Close with:** instrument `plan shown → expanded → revised → accepted` funnel in demo + Phase 2.

3. **No evidence on what a non-technical user's first 5 minutes actually looks like with vibe-fence.** The closest are the Brazilian hackathon study (N=31 teams, computing+non-computing students, observational) and the Fontys practitioner report (n=107 reflections, no control) — both students, neither vibe-fence's actual target (e.g. a retail ops manager with a real deadline). The `~10-minute first working version` baseline (Lovable/Builder) is vendor documentation, not an independent measurement. — Close with instrumented onboarding funnel: `init → first prompt → first artifact verified → first fence finding shown → first approved fix`.

4. **No data on whether "Turbo" (or any mode label) is understood, trusted, or invites recklessness with non-technical users.** minimax (U-04b) surfaces the naming risk via Antigravity's docs; no usability data exists for label wording on this audience. — Close with a 5-person label test before committing to user-facing copy (deepseek gap #9 proposes exactly this).

5. **No evidence for optimal queue cadence or multi-item parallelism.** Fitz et al.'s batching 3×/day RCT (smartphone notifications, n=237) is the closest anchor, but the transfer to code findings is untested. There is no data on how many in-flight agent tasks a novice can track; muse-spark caps at 8 visible, minimax caps at 1 concurrent — pure judgment, no measurement. **Close with:** default to 1 concurrent, ≤3 items per report, and measure override/dismiss rates before adding concurrency.

6. **No published accuracy / false-gate / latency budget for any vendor's classifier-in-the-loop.** Claude Code (Sonnet 4.6 transcript classifier, deliberately reasoning-blind), Cursor, Codex each run classifiers; none publish precision/recall, and Cursor's docs concede its allowlist is best-effort. vibe-fence cannot ship a classifier-based gate on borrowed credibility. **Close with:** ship deterministic containment for v1 (Phase 2 evals can trial a classifier behind a feature flag, measured against the same gate-budget metric).

7. **No evaluation of explanation tokens degrading agent task correctness in a coding harness.** A-04's context-bloat claim (Anthropic "context window is the #1 resource," `lost-in-the-middle`) is well-established, but no contributor measured "teaching tokens vs. task pass rate" in an agent companion. The proposed budgets (`max`≤8% of window, `medium`≤3%, etc. — deepseek A-07) are invented constants. **Close with:** log context utilization + task-pass-rate alongside dial level in Phase 2; until then treat the percentages as placeholder caps.

8. **Adversarial teaching channel unexplored.** A malicious repo can contain "instructions" that the agent paraphrases into a trusted teaching card the user accepts; GhostApproval (U-04) covers path misrepresentation, not prompt injection through the teaching channel. No contributor researched this attack surface. **Close with:** a dedicated hardening pass in synthesis across streams (touches Stream 04 guardrails).

9. **Thinned-stream meta-gap:** argon and gpt-6 absent → this stream likely under-represents primary education literature, accessibility/WCAG auditing, and open-weights inference-serving trade-offs that showed up in their other streams. Until the FINAL synthesis reconciles streams, treat any claim that depends on a single contributor's primary sources as provisional (see §7).

## 5. The consolidated answer

vibe-fence's companion is a fenced workshop, not a helpful roommate: the user remains the editor and the agent is the builder, but the workshop enforces the safety that the user cannot be competent to decide — project-root filesystem boundary, credential hard-deny, egress allowlist, and git checkpoint before every auto-fix, all of which survive even the most permissive mode and are what lets the companion move fast without asking. Teaching is scaffolding that fades: it starts at `max` for unfamiliar domains (explanation depth grows with structure, not verbosity) and steps down on verified streaks, because novices learn from worked examples and experts are harmed by them; the fade must be per-task-class, not per-user, otherwise the same harness simultaneously over-explains one thing and under-explains another. Turbo is not "skip the human" — it is "replace the human with deterministic containment for the classes the human demonstrably cannot adjudicate" (scope, exfiltration, credential reads, `npm run *` payloads), reserving prompts to ≤3/session for decisions a non-technical person can judge from the resolved target, diff, and consequence shown; a structured `What changed · Why · How to undo` card with an expand affordance is the only teaching surface, batched at checkpoint boundaries rather than mid-flow. The first artifact teaches more than the first sentence, so onboarding's job is one working thing on a link that the user built with one prompt, with the fence invisible until it has a completed fix to deliver and permission levels named by the guarantee they give, not the speed they promise.

## 7. Open questions we could not resolve

> Larger and more consequential than in the other streams because the evidence base was thinnest here. Each question names the experiment that would settle it.

- [ ] **Does hint-first actually beat explain-loudly *in a coding companion for non-technical users*?** Bastani et al. (PNAS 2025, n≈1,000, high-school math) is the only large field experiment anyone found; its magnitudes (+48%/+127%/−17%) are math-task numbers. No study tests hint escalation or `TODO(human)`-style handoffs on non-technical builders. *Experiment:* same codebase, same task, A/B `max` as verbose lecture vs. deepseek's hint-first (symptom→question→timeout→explanation) vs. minimax's structured forced-choice; outcome = can the user fix a *similar* issue unassisted next time (transfer check — proposed by muse-spark gaps, deepseek O-05, minimax). Treat until then: the direction (answer-only harms retention; hint-first helps) is `proven` in education; the magnitude and the correct `max` dosage for vibe-coding are unknown.
- [ ] **Should the dial ship as visible UI in v1, or as an invisible competence tracker?** muse-spark and deepseek want a friendly `fence dial <level>` with auto-suggest; minimax warns that a visible dial is one more thing a beginner must understand on day one (O-01), which is the tension that makes this an open question. Deepseek gap #4 and gemini/minimax explicitly note no evidence on whether dialect comprehension correlates with learning intent. *Experiment:* 5-person usability test on label/prompt wording (deepseek gap #9; minimax U-04b) + A/B visible vs hidden in demo, measuring activation (time-to-first-fix) vs. retention (transfer check). Interim stance: ship the *state file* as the architecture; expose only a global shortcut in the UI.
- [ ] **What is the right gate budget and fade trigger?** "≤3 gates/session; step down after 5 consecutive verified fixes of same rule; step down a domain after 3 clean sessions" are recurring proposals but are pure judgment — no contributor cited an empirical threshold for coding tasks. Muse-spark gaps #1–2, deepseek gaps #8–10, minimax §6 all flag this. *Experiment:* sweep 1→5 gifts; instrument approval rate + override rate + dismiss rate; pick the Pareto knee.
- [ ] **Is a classifier-based turbo worth its miss rate and latency for an on-device fence?** minimax's vendor-classifier survey vs. deepseek's "deterministic containment + reversibility covers more for far less" — neither side has a measurement of classifier precision/recall on vibe-fence's own categories (and no vendor publishes theirs). *Experiment:* deterministic v1 ships; Phase 2 runs a classifier behind a feature flag measured against the same gate-budget + findings-without-asking metrics; abort if the miss rate exceeds the deterministic perimeter's provable guarantees.
- [ ] **What queue cadence and concurrency does a non-technical user actually tolerate?** deepseek's "≤3 items, ≤1 decision at natural stops" leans on Fitz et al. smartphone batching (n=237, 3×/day) + developer queue inference (Linear 30% on first pass — self-reported on Linear's own codebase); no measurement exists on novices tracking multiple in-flight fixes. muse-spark caps at 8 visible; minimax at 1 concurrent. *Experiment:* vary items-per-report (1/3/5) and concurrency (1/2); outcome = approval-reflex rate (deepseek U-08's rolling 90% signal) and undo usage.
- [ ] **Is the adversarial teaching-channel surface real?** No contributor researched "malicious repo instructions → agent paraphrases them into a trusted teaching card." *Experiment:* dedicated red-team pass on the teaching injection (touches Stream 04); not a UX experiment.
- [ ] **Stream-05-specific meta-question:** **Does the thinning itself bias the synthesis toward safety-first readings?** The missing contributors (argon, gpt-6) were exactly those that might have surfaced primary education-field studies, WCAG/accessibility auditing for the card UX (muse-spark gap #4), and open-weights inference cost arguments that would challenge the classifier/budget design — none of which the four present contributors covered adequately. Treat sections marked `thin:3/4` as the places where this selection bias, if it exists, would live. The FINAL synthesis should cross-check them against argon's and gpt-6's primary-source tables from Streams 01–03.
