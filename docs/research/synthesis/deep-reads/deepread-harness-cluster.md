## DOC A — Lilian Weng, *Harness Engineering for Self-Improvement* (Lil'Log, 2026-07-04)

1. **Title/authors/date:** *Harness Engineering for Self-Improvement* — Lilian Weng — 2026-07-04 (blog synthesis, ~31 min read, 38 refs).
2. **Thesis (2–3s):** Near-term RSI will not be a model rewriting its own weights but a model rewriting its *harness* — the deployment system (workflow, tools, memory, evaluation, permissions). Once harness design is code, a capable coding agent can exploit the same search space human engineers use; improvements then internalize into model weights only later (cf. prompt-engineering → instruction tuning).
3. **Key results/metrics cited (not primary exps):** Surrogate evidence only — STOP improves mean performance with GPT-4 but degrades with GPT-3.5/Mixtral (capability gate); Lin et al. 2026: harness-updating ability flat from Qwen2-32B → Opus 4.6, but harness-benefit is non-monotonic (mid-tier benefits most); AHE > OpenCode/Terminus-2/Codex on Terminal-Bench-2 except Hard tier and transfers to SWE-bench Verified; AlphaEvolve ablations show evolution+context+meta-prompt+full-file+stronger LLM all matter; failure-mode taxonomy (defaults drift, impl drift, context collapse, over-optimism/eureka-ing, tacit knowledge, weak taste).
4. **Method:** Taxonomic survey organizing auto-research, evolutionary program search, ADAS/AFlow/ACE→MCE→Meta-Harness→Self-Harness→AHE→DGM/Hyperagents→SIA/Continual Harness into progression: prompts→structured context→workflows→harness code→optimizer code. Five harness design patterns (workflow loops, FS-as-memory, subagents, tool surface) + three optimization families (context engineering, workflow design, self-improving harness) + evolutionary search.
5. **Blind spots:** No controlled comparison at fixed harness (conflates model + harness); heavy reliance on TB2/SWE-bench Python — no non-technical vibe-coder pop (FINAL-v3 B-01); benchmark leakage / overfitting risk and reward-hacking unaddressed beyond warnings; "human moves up the stack" is normative not operational; publication bias (negative results hidden) acknowledged but not solved.
6. **Vibe-fence implications:** **S-07** — don't stack greedily; CCI factorial (Lil'Log's ADAS/AFlow/ACE stacking echoes this) → require isolation+combination A/B. **S-06/S-11** — editable surface must be narrow + outside evaluator (permission control lives outside self-edit loop); self-editable harness that includes its own verifier is broken boundary — validates FINAL-v3's `tools/` outside write-scope + shadow checkpoint. **B-05/B-07** — teaching↔correctness unmeasured; verifier quality on hobby repos 11.3% flaky on curated → worse on hobby. **M2/M4** — treat harness as empirical state transition (manifesto + predicted impact + falsifiable edit), not prompt growth.

## DOC B — Zhang et al., *Self-Harness: Harnesses That Improve Themselves* (arXiv:2606.09498, PJLab, 2026-06-12)

7. **Title/authors/date:** *Self-Harness: Harnesses That Improve Themselves* — Hangfan Zhang, Shao Zhang, Kangcong Li et al. (PJLab, corresp. Lei Bai/Shuyue Hu) — 2026-06-12 (v1 cs.CL).
8. **Thesis:** A fixed LLM can improve its *own* harness without a stronger teacher by a closed propose→evaluate→accept loop: weakness-mining clusters verifier-grounded failures → same model as proposer emits K diverse *minimal* edits → regression gate (Δ held-in ≥0 ∧ Δ held-out ≥0 ∧ max>0) merges only non-regressive edits. This makes harness design model-specific and auditable.
9. **Key results (Terminal-Bench-2.0, 64-task subset, minimal DeepAgent initial harness, Harbor containers):** MiniMax M2.5 pass 43.0→50.0 held-in (+16% rel) / 40.5→61.9 held-out (+53% rel, +21.4pp); Qwen3.5-35B-A3B 15.1→36.0 held-in (+138% rel) / 23.8→38.1 held-out (+60% rel); GLM-5 47.7→57.0 / 42.9→57.1 (+33% rel). All via 3–4 accepted edits; trajectory shows many rejections then merge. Edits are targeted (artifact-early-creation, schema tags, loop caps, dep precheck, middleware recovery, PATH persistence) not prompt bloat. Evolution from 42.2→53.9% (M2.5) / 20.3→36.7% (Qwen) overall lineage.
10. **Method:** Algorithm 1 — fixed model M, h₀, D_in/D_ho, evaluator E. Loop T: EVALUATE → BUILD-EVIDENCE-BUNDLE (failure signature ϑ=(c,q,m): terminal verifier cause, causal behavior status, abstract mechanism; exact-match clustering, ordered by support/actionability) → PARALLEL-PROPOSE (K distinct proposals, each grounded in one mechanism + editable surface + audit record, preserving passing behaviors, summarized prior edits) → validate each candidate via 2× repeated eval (stochasticity reduction) and acceptance rule; merge accepted. Editable surfaces = declared config points in harness definition file (system prompt, memory sources, skills, bootstrap/execution/verification/recovery instructions, runtime policy).
11. **Blind spots:** 64-task filtered subset (unstable/ multimodal excluded → generalizability gap); 3 models only, one small MoE (Qwen-35B-A3B weakest baseline inflates relative Δ); held-out = same bench distribution not truly unseen skill/bench (TRANSFER-CHECK); no adversarial robustness of proposer; merge compatibility untested; compute cost per iteration (64×concurrency × repeats) unreported; dependence on strong verifier quality (FINAL-v3 B-07).
12. **Vibe-fence implications (high leverage):** **S-01/S-09/BILL-01/PRV-09** — Self-Harness's editable surface is exactly `.fence/rules/*.json + src/framework/*.ts` with hash attestation (S-06a/GEM-11); adopt its `ϑ=(c,q,m)` 3-tuple clustering as `.fence/verifier` failure-manifesto schema (S-06a, B-07). **S-05** — deterministic fence decides; evaluation system distinct from optimizer, rerun verifier after harness rewrite (not just prompt patch). **S-04/C-10** — require `tests×2` trust ladder + `Δ held-in ∧ Δ held-out` gate before promoting generated smoke tests; treat `unknown≠pass`. **M4** — adversary bench (8–12 tasks incl. poisoned AGENTS.md) is missing regression gate analog; add it. **M1–M2** — ephemeral verifier `src/framework/verifier.ts` is the local analog of their weakness-mining bundle.

## DOC C — Shao et al., *Context Language Models* (arXiv:2609.37725, UW + Meta Superintelligence Labs + MIT, 2026-09-30)

13. **Title/authors/date:** *Context Language Models* — Rulin Shao, Shannon Shen (MIT), Junjie Oscar Yin, Yuetai Li, Minheng Wang, Hamish Ivison, Radha Poovendran, Nathan Lambert, Teng Xiao, Mike Lewis, Wen-tau Yih, Luke Zettlemoyer, Pang Wei Koh — 2026-09-30 (Code: facebookresearch/context-language-models).
14. **Thesis:** Move context management *from harness policy into model behavior*: mirror live context as an editable file (`L_{t+1}=N^{CLM}(L_t)` vs append-only `L_{t+1}=L_t → N(L_t)` ). Zero-shot CLMs with bare Bash already outperform SOTA compaction/offload harnesses; crucially they become *learnable* in-context (skill evolution) and in-weights (success-gated RL) while SCR recovers serving efficiency.
15. **Key results/metrics:** Zero-shot (Qwen3.6-27B@32K): BCP 59.4% accuracy, +11.4% rel over Codex summary with −21.5% prefix-reuse PFLOPs; TB2.1 matched-best accuracy with −29.5% FLOPs. Math-opt (Claude 4.6 Sonnet): CLM best-of-run on all 4 (circle 2.636 vs OE 2.541; Erdős overlap 0.3810 competitive). EdgeBench-10 12h: CLM 44.6 vs summary 42.3 at 179 vs 437 PFLOPs (Qwen3.6-27B); Claude 51.0 vs 42.3. Software World 24h 6-repo swarm: +65% downstream speedup vs summary. In-context steering: 1 sentence shifts threshold/boundary/backup; evolution: ContextBench KV Store 22.3→83.8% dev / 38.3→74.2% held-out, Log Triage 0→100%. RL (Qwen3.5-9B on OpenResearcher → BCP): CLM 28.8→42.5% (+47.6%) at 1.52→1.34 PFLOPs (vs summary 34.7→42.1% at 4.01→2.19 PFLOPs; CLM −38.8% FLOPs at matched accuracy). SCR: 65% of SGLang FLOPs (−35%), Z=6 saturates; 7.8% prompt-token reuse beyond prefix cache (5.3 reasoning-strip, 2.5 edits). ContextBench: selective retention / surgical editing / offload+retrieval diagnostics.
16. **Method:** Context-as-file impl: live context file at `/tmp/.live_ctx/LIVE_CTX_MAIN.txt`, Bash edits auto-sync to server; if no edit, default append. Multi-agent = multiple context files. Learning: (a) instructed steering (1 sentence), (b) prompt-evolution loop (6 train + 12 extra → 102 dev, proposer = Claude Fable 5.1 assisted or Opus 5 self), Pareto-select on frontier, (c) stepwise GRPO: trajectory advantage broadcast to segments, success-gated efficiency advantage `V^e = clip((\bar{L}_T − L_S)/\bar{L}_T)` within successful group (|success|≥2), combined `V=V^out+0.25 V^e`. Serving: Suffix Cache Reuse (SCR) relocates up to Z=6 longest surviving spans post-edit, re-rotates RoPE, session-private slots; hybrid Gated DeltaNet snapshots recurrent state. Benchmark ContextBench (4 tasks: Needle Retention, Sudoku Sketchpad, KV Store, Log Triage) isolates context mgmt from knowledge.
17. **Blind spots:** Safety: editable live context is new prompt-injection channel (author-cited OpenAI 2026b self-generated injections) — conflicts with S-06/S-11 containment. Context-length awareness weak (bucketed estimates 6.2K/9.8K/10.4K; underestimation for Claude); gains partly scale with model size (Qwen-9B edits 1.4×/task vs 2.6× for 27B, higher peak 30.2K). "No edit → append" default inherits prompt growth if model never acts. SCR is approximate for full-attention, none for linear layers (hybrid correctness bound unproven). 12h/24h runs = cost not vibe-coder comparable (B-01/B-06).
18. **Vibe-fence implications:** **S-03/S-05** — CLM proves byte-capped 4KB + metadata-only exposure can be replaced by *learned* compact-and-offload; but FINAL-v3's deterministic fence must remain — treat context edit as `unknown→warn` not `pass`. Gate: edits that drop block-relevant evidence (`secrets/RLS/billable-loop`) auto-reject. **S-01/S-11** — AGENTS.md ≤400tok router + checkpoint-then-edit + ephemeral verifier is the safe subset of CLM; FS-as-memory already in FINAL-v3. **M2-M4** — borrow CLM skill-evolution harness-to-CLM distillation for Teaching Dial (`max→medium→min→silent`) as skill loop, not Turbo containment. **B-04/B-08** — editable-context channel + Turbo bypass risk: keep `.fence/hooks/postinstall` outside writable surface (S-06a GEM-01). **Visceral Delta (S-14):** demo should show before/after token trace (PFLOPs) not just pass rate — CLM's 35–60% compute delta is the visceral cue.

## Cross-cut (harness cluster thesis)

19. Together the three docs mark a shift: **harness = code over protocol engineering** (LilLog pattern) → **harness improvement is auditable empirical state transition** (Self-Harness Δ-in/Δ-ho regression gate, observable manifesto) → **context management migrates from harness to model** (CLM context-as-file).
